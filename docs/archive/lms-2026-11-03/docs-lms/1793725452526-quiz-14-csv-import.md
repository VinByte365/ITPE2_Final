## Design system constraints (spec 04)

- No raw hex in JSX or CSS. One stylesheet: `src/index.css`. No Tailwind/CSS-in-JS/extra CSS files.
- Every `className` must resolve to a selector in `src/index.css`; add the rule when adding the class.
- Icons only from `src/components/Icons.jsx` (extend it; no emoji).
- Inline `style={{}}` only for genuinely dynamic values.
- No semantic hues: express invalid/attention state with icon + text label + `--accent-ink` (attention), never red alone.
- Works at 360 px, 44 px touch targets, keyboard-usable, `aria-disabled` on non-actionable items.

## Data flow

1. Faculty opens QuizBuilder for a topic; built-in mode selected → import section visible.
2. Faculty picks a CSV file → Papa.parse parses client-side → `rowToQuestion` maps each row to the API question shape.
3. Preview table lists each question with a validity flag and row-level issues; invalid rows block confirm.
4. Faculty clicks Confirm → `importQuestions(quizId, questions)` POSTs `{questions: [...]}` to the backend.
5. Backend validates atomically: any invalid row → 422 `VALIDATION_ERROR` with row-level `details`; total > 20 → 422 `QUIZ_QUESTION_COUNT`; on success returns created questions.
6. Frontend reloads the question list via `onImported` and clears the preview.
